# Modules, entry points and ownership

The backend owns model credentials, accepted state and execution. The renderer
consumes a read projection. The shell packages the renderer. A command wrapper
does not become a second scheduler or a new configuration source.

| Module or helper | Owner / caller | Input → output | Dependencies, state and effects | Proof / availability |
| --- | --- | --- | --- | --- |
| `scripts/validate_search.py` and `ora.retrieval.validation_transport` | Explicit provider-only qualification | Selected cases and batch allowance → saved adapter records and private summary | Existing discovery adapters, private durable HTTP counter, OSRA credentials; no model calls or fallback | No-call default; injected cap/restart/capture tests; [validation plan](search-validation-plan.md) |
| `scripts/validate_search_agent.py` and `ora.retrieval.agent_validation_budget` | Explicit natural search evaluation | Natural start request or exact closed-parent follow-up → real mission records and usage accounting | Full catalog, isolated selected profile, durable HTTP counter; bounded defaults or explicitly authorized accounting-only mode; optional parent-state clone | Injected source-delivery, profile isolation, limit/accounting and negative-retrieval checks; live results are case-specific |
| `ora.contracts.models` | Shared interface / backend and clients | Typed records → validation and JSON Schema | Pydantic; no network or writes | Accepted/rejected shared fixtures |
| `ora.contracts.generate` | Shared interface / development wrapper | Canonical models → schemas and examples | Files only; `--check` is read-only | Drift check; TS generated by `scripts/generate-types.mjs` |
| `ora.contracts.service` | Interface example / offline tests | Versioned command → receipt and event | SQLite transactions; synthetic artifacts only | Deduplication, stale versions, peer requests, delayed operations, restart |
| `ora.contracts.resources` | Interface example / offline tests | Mission/task/attempt → private scratch and port | OS loopback port and temporary files | Concurrent isolation and stale-owner cleanup rejection |
| `ora.benchmarks` | Evaluation / evaluator and packet exporter | Frozen public sources → worker packet; separate key → evaluation | Standard library, read files; explicit export writes | Hash, future-event and withheld-reference tests |
| `ora.benchmarks.context_recovery` | Evaluation / explicit saved-run scorer | Versioned synthetic case and exact request/source/output selection → mechanical checks and separate semantic review | Read-only state inspection; no model dispatch; withheld criteria excluded from worker input | [Context efficiency](stage4-context-efficiency.md); injected fixtures do not qualify live model behavior |
| `ora.skills` | Agent capability package / role loader | Role/skill manifest and capabilities → available packages | Pydantic; read-only imports; per-attempt mutable state | Reference failures, provenance and two-role reuse |

| `ora.models.token_estimate` | Request admission / exact serialized preview and saved-basis checks | Canonical request bytes → versioned token estimate and fallback reason | Pinned local vocabulary; no runtime download; native and unsupported shapes retain legacy estimates | [Working context](stage4-context.md); empirical calibration is separate from provider admission and scientific quality |
| `ora.credentials` | Credential selection / mission host and model adapter | Nonsecret profile label and trusted local mapping → pinned quota domain | Reads profile configuration without keys; selected key is resolved only at the provider boundary | Explicit profile selection, shared/default domains, mapping drift and no-fallback tests |
| `ora.coordination.traces` and `trace_inspect` | Host observations / read-only diagnostic clients | Correlated accepted events → paged readable steps, usage and progress metadata | Shared StateStore; returned reasoning requires separate trusted diagnostic access | Redaction, unknown/cyclic ancestry, replay and disconnected-viewer fixtures |
| `ora.observability`, `scripts/trace_run.py` and `scripts/report_api_runs.py` | Local diagnostics / explicitly invoked export | Saved run receipts and validation ledgers → token/cache coverage, measured timing, readable comparisons and metadata-only spans | Local inspection is read-only; OpenTelemetry and cloud export are optional, with recorded acknowledgements | [Local traces](observability.md); missing usage stays unknown, observation windows differ from HTTP duration, and uncertain exports are not automatically resent |
| `ora.coordination.demo` and `inspection` | Development / explicit local commands | Fresh offline callbacks → canonical saved Atlas projection | Demo writes a new supplied state directory; inspection reads only | Exact client/CLI equivalence, no fabricated report or provider execution |
| `ora.coordination.contributions` and `contribution_inspect` | Peers / host and read-only clients | Exact shared updates → optional peer statements and paged proposal discussion | Existing board/mailbox/state and safe projections; no model call or consensus gate | Unknown use, late-peer critique, clarification, exact version replay and private-reference checks |
| `ora.coordination.contribution_demo` | Development / explicit offline command | Fresh base fixture → shared contribution and explanation-coverage review | Disposable state only; exports the same projection used by Codex and Atlas | Original snapshot retained; no provider call or scientific report; explicit old/new summary boundaries |

| `ora.evidence.intake` and `windows` | Source readers / mission tools and qualification | Fetched bytes or a retained copy → classified source, checked passages and a continuation cursor | Parses selected HTML/XML/PDF/text; preserves original bytes, locators and current use records | [Intake](stage4-intake.md); parsing, reading windows and actual HTTP qualification do not certify scientific claims |

| `ora.evidence.navigation` | Source-window reader | Verified extracted block locators → bounded section offsets | Navigation-only metadata; no new passages, rewritten mappings or relevance judgment | [Source walkthroughs](source-quality-walkthroughs.md); exact offsets, repeated-window feedback and current-use checks |

| `ora.evidence.coverage` | Reading progress / mission context | Exact selected passages and saved windows → covered and missing extracted-text ranges | Read-only hash, locator and extraction checks; no source text in the result | Detects skipped ranges and partial originals; completeness describes retained extracted text, not model understanding |

| `ora.mission.tool_catalog` | Model-facing tool declarations / mission service | Static capabilities, descriptions and argument schemas → saved tool manifests | Composes retrieval and observation tool declarations; no model calls or persistent writes | Catalog and service fixture checks; moving declarations does not establish a latency change |
| `ora.mission.direct_citations` | Direct-answer preservation / mission service | Explicit citation markers and checked producing-input passages → exact citation links and provenance | Read-only record resolution; no model calls or claim-support inference | Exact-marker, ambiguity and producing-input integration tests |
| `ora.mission.report_lineage` | Report acceptance and current views / mission service and context | Exact producing call, request and context references → source dependencies and current use | Rechecked inside report-save and acceptance transactions; current views withhold revoked text while immutable history remains | Post-dispatch revocation, later reads, source-free controls and projection-race tests; no scientific-support inference |
| `ora.mission.shared_materials` | Peer discovery / working context and internal readers | Same-mission scholarly hits and accepted sibling reports → compact titles, origin and exact references | No source admission or synthesized summary; excludes browser leads and private notes, rechecks current use | Scoped catalog, paging and prepared-input tests; discovery is not proof of reading or useful collaboration |
| `ora.mission.context` and `memory` | Working view / each selected agent turn | Current tasks, peer records and notes → included/omitted input receipt | Exact state references, paged detail and original model configuration; no independent scientific planner | [Context recovery](stage4-context.md); context inclusion is distinct from scientific use |

| `ora.mission.skill_activation` | Mission host / each new-run configuration | Pinned role catalog and peer choices → active skills and associated tool exposure | Mandatory instructions retained; explicit optional activation/release; old runs keep their loading policy | [Context efficiency](stage4-context-efficiency.md); model choice quality requires separate qualification |

Each future helper should reuse these records and service boundaries. Add it when
there is a caller and a behavior to verify; do not create empty packages that claim
to work. A changed shared interface updates its [compatibility record](../interfaces/compatibility.md).
Software versions and installation remain owned by [setup](setup.md).
