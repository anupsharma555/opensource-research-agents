# Modules, entry points and ownership

The backend owns model credentials, accepted state and execution. The renderer
consumes a read projection. The shell packages the renderer. A command wrapper
does not become a second scheduler or a new configuration source.

| Module or helper | Owner / caller | Input → output | Dependencies, state and effects | Proof / availability |
| --- | --- | --- | --- | --- |
| `ora.contracts.models` | Shared interface / backend and clients | Typed records → validation and JSON Schema | Pydantic; no network or writes | Accepted/rejected shared fixtures |
| `ora.contracts.generate` | Shared interface / development wrapper | Canonical models → schemas and examples | Files only; `--check` is read-only | Drift check; TS generated by `scripts/generate-types.mjs` |
| `ora.contracts.service` | Interface example / offline tests | Versioned command → receipt and event | SQLite transactions; synthetic artifacts only | Deduplication, stale versions, peer requests, delayed operations, restart |
| `ora.contracts.resources` | Interface example / offline tests | Mission/task/attempt → private scratch and port | OS loopback port and temporary files | Concurrent isolation and stale-owner cleanup rejection |
| `ora.benchmarks` | Evaluation / evaluator and packet exporter | Frozen public sources → worker packet; separate key → evaluation | Standard library, read files; explicit export writes | Hash, future-event and withheld-reference tests |
| `ora.skills` | Agent capability package / role loader | Role/skill manifest and capabilities → available packages | Pydantic; read-only imports; per-attempt mutable state | Reference failures, provenance and two-role reuse |
| `ora.state` | Mechanical persistence / domain modules | Accepted records and bytes → exact versions, references and events | SQLite transactions and immutable files; no model or network calls | Fault/restart, ownership, migration and backup/restore fixtures |
| `ora.agents` | Agent registry / future execution host | Named instances, selected configuration and granted capabilities → saved call manifests and local invocation receipts | Uses `ora.state` and `ora.skills`; explicit helper invocation, no implicit model dispatch | Collision, drift, input lineage, discovery/exposure and isolated failure tests |
| `ora.coordination.board` and `mailbox` | Scientific peers / host calls | Proposals, claims and exact references → accepted contributions and durable peer requests | Short StateStore transactions; no scientific ranking or model calls | Negotiation, stale owners, independent branches, delivery versus answer and targeted replay |
| `ora.coordination.capacity` and `executor` | Mechanical host / registered callbacks | Frozen work and resource policy → concurrent execution and atomic accepted records | asyncio plus shared SQLite; network and callback work outside transactions | Overlap, early dependent progress, quota/retry waits, conflict and restart fixtures |
| `ora.models.groq` and `session` | Selected-model boundary / explicit host invocation | Exact saved configuration, sources and tool history → request intent and captured response | Groq Chat Completions only when invoked; private blobs and durable dispatch marker; no implicit retry or model substitution | Offline protocol, source-use, backup and concurrent session/executor tests; separate bounded live protocol proof |
| `ora.coordination.traces` and `trace_inspect` | Host observations / read-only diagnostic clients | Correlated accepted events → paged readable steps, usage and progress metadata | Shared StateStore; returned reasoning requires separate trusted diagnostic access | Redaction, unknown/cyclic ancestry, replay and disconnected-viewer fixtures |
| `ora.coordination.demo` and `inspection` | Development / explicit local commands | Fresh offline callbacks → canonical saved Atlas projection | Demo writes a new supplied state directory; inspection reads only | Exact client/CLI equivalence, no fabricated report or provider execution |
| `ora.coordination.contributions` and `contribution_inspect` | Peers / host and read-only clients | Exact shared updates → optional peer statements and paged proposal discussion | Existing board/mailbox/state and safe projections; no model call or consensus gate | Unknown use, late-peer critique, clarification, exact version replay and private-reference checks |
| `ora.coordination.contribution_demo` | Development / explicit offline command | Fresh base fixture → shared contribution and explanation-coverage review | Disposable state only; exports the same projection used by Codex and Atlas | Original snapshot retained; no provider call or scientific report; explicit old/new summary boundaries |
| `scripts/measure_stage3_bursts.py` | Development / performance diagnosis | Declared serial/parallel workloads → timing, memory, backlog and durability receipts | Fresh child processes and SQLite stores; controlled callback and writer delays | Source-pinned measurements at tested sizes; not provider throughput or endurance proof |
| `ora.retrieval` | Provider boundary / reference adapters | Provider responses → canonical delivery, attempt, usage and hit records | Allowlisted redaction and `ora.state`; does not make search requests | Partial/error/quota responses, pagination, duplicate/retry and usage fixtures |
| `ora.evidence` | Shared evidence library / collectors and reviewers | Saved hits and identity assertions → publications, study families, copies and passages | Rights-aware retained bytes, exact links, scoped correction flags | Identity conflict, source integrity, correction and lexical lookup fixtures |
| `ora.state.inspection` and `ora.state.steps` | Shared review projection / Atlas and Codex | Exact snapshot and saved events → readable findings, provenance and diagnostic steps | Read-only projection; credentials/private instruction text excluded | Parent/child lineage, misleading references and damaged-source tests |
| `ora.state.views` | Shared database review / SQLite viewer and read-only inspector | Exact record revisions → small SQL overviews | Additive schema migration; no prompts or source bodies in overview columns | [State inspection](state-inspection.md); migration, version and privacy fixtures |
| `ora.state.demo`, `ora.state.inspect`, `ora.state.probe` | Development and review / explicit module commands | Recorded fixture or private local state → exports, read views or workload receipt | Demo/probe write only the supplied state directory; inspector opens read-only | [Commands and proof boundaries](stage2-verification.md); no provider activation |
| `ora.cli` | Developer/Codex / shared command surface | Explicit subcommand → module result | No implicit credentials or mission execution | CLI tests; sources and findings exported separately |
| `scripts/dev` | Repository setup / local, CI, cloud | Chosen setup/check action → observable command results | Pinned Python/Node; project-local installs/caches | Clean installation, lock hashes and same check commands |
| `ui/` | Review client / React Mac renderer | Canonical sample snapshots → navigable findings and diagnostics | React; local sample annotations only | Component journeys and native review |
| `desktop/` | Packaging / local Mac user | Built React assets → unsigned Tauri prototype | Rust, Cargo, platform WebKit/CLT | Embedded sample opens without Vite |
| `.agents/skills/os-check-foundation` | Codex development / coding task | Repository checkout → selected offline check receipt | Calls `scripts/dev`; no personal skill files | Local helper invocation; actual cloud discovery tracked separately |
| `ora.live` | Optional local Atlas / explicit CLI and authenticated loopback API | Start or exact-version follow-up → saved model/tool/peer work | SQLite, worker threads, Groq; private state and explicit spending allowance | [Local live scope and checks](live-research.md); supplied evidence only |
| `ora.live.provenance`, `provenance_schema`, `inspection` | Live provenance / explicit host and offline inspection commands | Saved calls and exact shared configurations → tool transitions and SQL overviews | Same SQLite database; explicit backed-up migration for legacy state | [Live provenance](live-provenance.md); unknown historical fields remain unknown |
| Production mission service | Later persistent-runtime delivery / API and peers | Authenticated command/query → durable mission events | Future auth, supervisor, stores and provider operations | **Unavailable**; CLI reports this explicitly |
| Connected source replay and run export | Later review service / app and Codex | Authenticated source/run request → permitted evidence/report | Local `ora.state.inspect` and recorded Atlas exports are implemented; remote transport remains future work | Local recorded inspection only; no production service claim |
| Store maintenance | Local operator / `ora.state.StateStore` | Explicit backup, restore or index rebuild → verified local state | SQLite snapshot and hash-verified files; new restore destination only | Implemented local APIs and fault tests; production scheduling/retention remains future work |

Each future helper should reuse these records and service boundaries. Add it when
there is a caller and a behavior to verify; do not create empty packages that claim
to work. A changed shared interface updates its [compatibility record](../interfaces/compatibility.md).
Software versions and installation remain owned by [setup](setup.md).
