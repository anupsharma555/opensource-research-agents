## Independent review and corrections

Review found and corrected real issues: a claimed model hash could hide a different
model, an operation result could be attributed to another task, unresolved
operations could be omitted from mission completion, uncertainty could regress
silently, unresolved artifact references could answer a request, and invalid replay
could poison a cursor. Regression checks exercise each correction. Scratch
ownership and event ordering are scoped to a mission so identical task IDs do not
interfere across missions.

The benchmark review added exact denominator spans rather than claiming an
uncited reference key was supported. Native review corrected navigation that
retained an old scroll offset and clarified the fixed follow-up receipt's lineage.
These are verified fixture/app corrections, not a claim that all future runtime
failure modes are solved.

## Git and concurrent development

The initial published foundation is commit `eb6a519d793683312dd163dc57d1d97c606984e1`,
tree `b3c1b86994356be40a1d74ce948b05c2a3dbf119`. GitHub private visibility was verified;
two fresh private clones matched those identities and passed the shared checks
without a project `.env` or lockfile changes. A publication-guard regression now
checks exact index blobs: a credential-shaped synthetic value staged before a
clean-looking working-tree edit cannot evade the check.

Two actual coding workers made disjoint documentation additions and an intentional
overlap in one canonical model docstring. The source worker committed `a98eed5` and
the runtime worker `02e2d9b`. A third clean clone observed conflicts in the model,
generated JSON Schema and generated TypeScript. The model was deliberately
reconciled, both derivatives regenerated, and both notes retained in merge
`c634710`. The resulting diff contained exactly five intended files. All three
lockfiles and an unrelated untracked note retained their original hashes. The
full offline suite passed afterward. These verification branches are examples;
the unrelated note and private integration receipts remain outside tracked source.

Private CI passed at the initial commit. An isolated verification branch then
changed a generated query contract's version from `1.0` to `0.9`. CI failed with
`Stale generated schema: contracts/generated/query.schema.json; run scripts/dev generate`,
confirming the failure was the intended contract drift. The canonical generator
restored the file in a subsequent commit. This did not modify `main`.

## Cloud preparation

The actual current Codex Cloud onboarding VM ran the same checks on Linux x86_64,
verified the commit and lock hashes, loaded the committed repository skill and
invoked its full helper. Its first setup failed at a read-only default Python
installation path; moving the installation below ignored `.local/` recovered it.
That observed repair now belongs to the shared setup wrapper.

Onboarding is not a published fresh-task result. Publication, fresh-task skill
discovery and retained output retrieval are recorded after observation; no missing
receipt is filled with an expected result. Native Mac behavior, live selected-model
fit and research endurance remain distinct checks.
