# Task planning

Use planning when uncertainty, several actions, or dependencies make a checkpoint useful. Simple tasks may finish directly. An optional scaffold is: goal; observable completion criteria; key uncertainties; next actions and dependencies; evidence or peer links; revision trigger; and a useful completion or pause condition. Use only the detail that helps the next decision. The rich guide has an adaptable example; it is not a required pipeline.

Create once with `save_plan`. Use `modify_plan` for later changes, supplying the last returned `expected_version`, a `revision_reason`, and only changed fields or stable step IDs. Omitted fields remain unchanged; supplied lists replace that field. `read_plan` retrieves current or historical state; reread after a stale-version rejection or when recovering missing context. Preserve evidence, dissent, negative results, and prior decisions unless the change explicitly revises them.

Plans record intent. Existing work proposals, peer requests, dependency waits, and publication perform actual work and completion. Saving or modifying a plan does not schedule, send, wait, or grant tools. Revise after meaningful evidence, feedback, or constraint changes; avoid edits that merely restate intent. A repetitive-edit diagnostic leaves other research available. While waiting, use an existing durable dependency wait rather than extra plan-refresh calls.
